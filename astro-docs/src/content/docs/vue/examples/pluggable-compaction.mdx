`compactor` is a purely additive override — `null` (the default) means
"use whichever built-in strategy `compactType` selects," so the two
props are never in conflict. A custom compactor's `compact(layout, cols,
context)` **must return a new array**, never mutate `layout` or its
items in place. Runs at every trigger point the built-in strategies
already run at: drag/resize end, item add/remove, mount, breakpoint
change, and `compactNow()`/`rearrange()`.

The `compactor: verticalFastCompactor` option in the demo plugs in
`verticalFastCompactor` (exported from `keystone-dashboard-layout-vue`):
the same result as the default vertical compactor in roughly O(n log n)
instead of O(n²). With four items there is nothing to see, since it only
starts to matter from a few hundred items. It is opt-in through
`compactor`, exactly like a custom one, and `compactType` keeps
selecting the original algorithm.
