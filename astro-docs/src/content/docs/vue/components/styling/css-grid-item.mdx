---
title: Styling → GridItem
description: The CSS classes GridItem's root element conditionally applies.
---

`GridItem`'s root element always has the class `vue-grid-item`, plus a
combination of the conditional classes below depending on its current
state. Target these directly, after the library's stylesheet is loaded:

```css
/* After importing '@keystone-dashboard-layout/vue/style.css' */
.vue-grid-item {
  background: #1e293b;
  color: white;
}
```

## Conditional classes

| Class | Applied when |
|---|---|
| `css-transforms` | `useCssTransforms` is true (the default) — positioned via CSS `transform` instead of `top`/`left`. |
| `disable-userselect` | A drag is in progress. **Note:** the stylesheet's own rule for this is actually named `.disable-user-select` (with a hyphen between "user" and "select") — a real, confirmed mismatch in the library's own source between the class the component applies and the class its stylesheet defines, so this specific rule never actually matches anything applied at runtime. Text selection during drag isn't currently prevented by this mechanism as a result. |
| `no-touch` | On Android, when the item is draggable or resizable — overrides default touch handling so drag/resize gestures work correctly. |
| `render-rtl` | The item is currently rendering right-to-left. See [Mirrored (RTL)](/vue/examples/mirrored-rtl/). |
| `resizing` | A resize is in progress. |
| `vue-draggable` | The item is currently draggable (resolved from its own prop or the parent layout's default), not static, and edit mode is on. |
| `vue-draggable-dragging` | A drag is in progress (same condition as `disable-userselect`). |
| `vue-grid-item-has-header` | The `#header` slot is actually provided — switches to a vertical flex layout splitting header/body. See [GridItem slots](/vue/components/grid-item/slots/). |
| `vue-grid-item-selected` | The item is part of the current `multiSelect` selection. See [Multi-select & group move/resize](/vue/examples/multi-select-group-move-resize/). |
| `vue-resizable` | The item is currently resizable, not static, and edit mode is on. |
| `vue-static` | `isStatic` is true. See [Static items](/vue/examples/static-items/). |
| `vue-use-radius` | `useBorderRadius` is true. See [Border radius](/vue/examples/border-radius/). |

## The close button

Rendered internally as a `<button class="btn-close">` when
`showCloseButton && enableEditMode && !isStatic`. Style it directly:

```css
.vue-grid-item .btn-close {
  background: #ef4444;
}
```

...or replace it entirely with your own — see
[Custom drag handle & close button](/vue/examples/custom-drag-handle-close-button/),
which uses the library's own exported `CustomCloseButton` component
instead of the built-in button.

## Border radius

Set via an inline style (not a class) computed from the `borderRadiusPx`
prop, applied whenever `useBorderRadius` is true — see
[GridItem props](/vue/components/grid-item/props/) and
[Styling → Variables](/vue/components/styling/css-variables/) for the
SCSS-level default that applies when you don't set `borderRadiusPx`
yourself.
