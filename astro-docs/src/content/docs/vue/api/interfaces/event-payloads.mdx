---
title: Cross-grid & outside-drop event payloads
description: The typed payloads for GridLayout's cross-grid and outside-drop events.
---

```ts
interface IOutsideItemDropped {
  x: number;
  y: number;
  w: number;
  h: number;
  dataTransfer: DataTransfer | null;
}
```

Payload for `item-dropped-from-outside`. `w`/`h` always echo
`outsideDropWidth`/`outsideDropHeight` back, so a handler doesn't need
to separately track what it configured. `dataTransfer` is the native
object from the browser's own `drop` event — read whatever the dragged
element attached to it (typically via [`readOutsideDropPayload`](/vue/api/interfaces/svg-export-and-payload/))
to decide what this drop actually represents; the library has no way to
know on its own, so nothing is added to `layout` automatically.

```ts
interface ICrossGridItemDropped {
  item: ILayoutItem;
  sourceLayoutId: string;
}
```

Payload for `cross-grid-item-dropped`, fired on the **target** grid —
the moved layout item (already inserted into this grid's `layout`) and
the source grid's `layoutId`.

```ts
interface ICrossGridDropRejected {
  itemId: string | number;
  sourceLayoutId: string;
}
```

Payload for `cross-grid-drop-rejected`, fired on the **target** grid
when it has `disableExternalDrop` set — the item stays in its source
grid; nothing about either grid's `layout` changes.

See [GridLayout events](/vue/components/grid-layout/vue-events/) for
when each of these actually fires, and
[Drag, drop from grid to grid](/vue/examples/cross-grid-drag-drop/) /
[Cross-grid drop restrictions](/vue/examples/cross-grid-drop-restrictions/) /
[Drag, drop from outside](/vue/examples/outside-drag-drop/) for working
examples.
