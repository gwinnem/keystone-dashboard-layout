Confirmed directly against `packages/react/src/index.ts`, the package's

## What this package exports

```ts
import {
  GridLayout,
  GridItem,
  GridItemDragHandle,
  GridItemCloseButton,
  useLayoutStorage,
  useLayoutPresets,
  type IGridLayoutProps,
  type IGridItemProps,
  type IGridItemDragHandleProps,
  type IGridItemCloseButtonProps,
  type IGridLayoutHandle,
  type IUseLayoutStorageReturn,
  type IUseLayoutPresetsOptions,
  type IUseLayoutPresetsReturn,
} from 'keystone-dashboard-layout-react';
```

That's the complete list. Unlike the Vue package, this package doesn't
re-export layout-data types, enums, or compaction/ARIA interfaces
through its own barrel — those come from the shared
`keystone-dashboard-layout-core` package directly instead (see below).

## Components

`GridLayout`, `GridItem` — see [Components](/react/components/) for
full prop documentation. Their prop types (`IGridLayoutProps`,
`IGridItemProps`) are directly importable, useful for typing a wrapper
component's own props.

### GridItemDragHandle

A small, ready-made drag-handle widget — the React port of Vue's own
`CustomDragElement.vue`. Not used internally by `GridItem`/`GridLayout`
themselves; place it inside a `GridItem`'s own children when you want
dragging restricted to a single handle rather than the whole item,
paired with that layout item's own `dragAllowFrom` field (e.g.
`dragAllowFrom: '.kdl-draggable-handle'`).

| Prop | Type | Default | Description |
|---|---|---|---|
| `text` | `string` | `'x'` | Label rendered inside the handle's own button |

See [Custom drag handle & close button](/react/examples/custom-drag-handle-close-button/)
for it in context, or reach for a plain element with `dragAllowFrom`
instead when you want full control over markup and styling.

### GridItemCloseButton

The default close button rendered inside a `GridItem` when its own
`showCloseButton` resolves `true` — the React port of Vue's own
`CustomCloseButton.vue`. Also exported standalone for rendering the
identical button elsewhere (e.g. a custom header) and wiring it to the
same removal logic manually.

| Prop | Type | Description |
|---|---|---|
| `i` | `string \| number` | The id of the `GridItem` this button removes when clicked (required) |
| `onRemoveGridItem` | `(id: string \| number) => void` | Called with `i` when clicked |

## Interfaces

| Interface | Covers |
|---|---|
| [Imperative handle (IGridLayoutHandle)](/react/api/interfaces/imperative-handle/) | The `ref`-based API `GridLayout` exposes — `compactNow`, `undo`/`redo`, selection, align/distribute, SVG export, `scrollToItem`/`focusItem` |

| `IUseLayoutPresetsOptions` / `IUseLayoutPresetsReturn` | Options/return shape of `useLayoutPresets` |

## Functions & hooks

| Export | Purpose |
|---|---|
| `useLayoutStorage` | A hook wrapping `localStorage` (or any `Storage`-compatible backend) persistence for a `layout` array |
| `useLayoutPresets` | Save and switch between several named layout arrangements |

## From `keystone-dashboard-layout-core`

The layout-data shape and framework-agnostic grid math live in `core`
rather than being re-exported from this package's own barrel. Import
these directly from `keystone-dashboard-layout-core` when you need
them:

```ts
import type {
  TLayout,
  ILayoutItem,
  IGridAriaLabels,
  ICompactor,
  IExportLayoutAsSvgOptions,
} from 'keystone-dashboard-layout-core';
import { ECompactType } from 'keystone-dashboard-layout-core';
```

`core` is the same package the Vue port uses underneath, so the shapes
themselves are identical either way — see this package's own reference
pages for the full field-by-field breakdown of each, framed for this
package specifically:

- [Layout interface (ILayoutItem)](/react/api/interfaces/layout/)
- [ARIA labels (IGridAriaLabels)](/react/api/interfaces/aria-labels/)
- [Pluggable compaction (ICompactor)](/react/api/interfaces/compactor/)
- [SVG export & outside-drop payload](/react/api/interfaces/svg-export-and-payload/)
- [Layout types (TLayout, TResponsiveLayout, TBreakpoint, TBreakpoints)](/react/api/types/layout/)
- [ECompactType](/react/api/enums/compact-type/)

See [GridLayout props](/react/components/grid-layout/props/) and
[GridItem props](/react/components/grid-item/props/) for where each of
these actually gets used.
