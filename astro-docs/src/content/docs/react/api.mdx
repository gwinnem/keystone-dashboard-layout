Confirmed directly against `packages/react/src/index.ts`, the package's
real public entry point — not assumed from the components alone.

## What this package exports

```ts
import {
  GridLayout,
  GridItem,
  useLayoutStorage,
  useLayoutPresets,
  type IGridLayoutProps,
  type IGridItemProps,
  type IGridLayoutHandle,
  type IUseLayoutStorageReturn,
  type IUseLayoutPresetsOptions,
  type IUseLayoutPresetsReturn,
} from '@keystone-dashboard-layout/react';
```

That's the complete list. Unlike the Vue package, this package doesn't
re-export layout-data types, enums, or compaction/ARIA interfaces
through its own barrel — those come from the shared
`@keystone-dashboard-layout/core` package directly instead (see below).

## Components

`GridLayout`, `GridItem` — see [Components](/react/components/) for
full prop documentation. Their prop types (`IGridLayoutProps`,
`IGridItemProps`) are directly importable, useful for typing a wrapper
component's own props.

## Interfaces

| Interface | Covers |
|---|---|
| [Imperative handle (IGridLayoutHandle)](/react/api/interfaces/imperative-handle/) | The `ref`-based API `GridLayout` exposes — `compactNow`, `undo`/`redo`, selection, align/distribute, SVG export, `scrollToItem`/`focusItem` |
| [Layout persistence](/react/api/interfaces/layout-persistence/) | `useLayoutStorage`, `useLayoutPresets`, and their option/return types |
| [Cross-grid & outside-drop event payloads](/react/api/interfaces/event-payloads/) | `onCrossGridItemDropped`/`onCrossGridDropRejected`/`onOutsideDrop` payload shapes |
| `IUseLayoutStorageReturn` | Return shape of `useLayoutStorage` |
| `IUseLayoutPresetsOptions` / `IUseLayoutPresetsReturn` | Options/return shape of `useLayoutPresets` |

## Functions & hooks

| Export | Purpose |
|---|---|
| `useLayoutStorage` | A hook wrapping `localStorage` (or any `Storage`-compatible backend) persistence for a `layout` array |
| `useLayoutPresets` | Save and switch between several named layout arrangements |

## From `@keystone-dashboard-layout/core` instead

The layout-data shape and framework-agnostic grid math are shared with
the Vue package, and live in `core` rather than being re-exported here.
Import these directly from `@keystone-dashboard-layout/core` when you
need them:

```ts
import type {
  TLayout,
  ILayoutItem,
  IGridAriaLabels,
  ICompactor,
  IExportLayoutAsSvgOptions,
} from '@keystone-dashboard-layout/core';
import { ECompactType } from '@keystone-dashboard-layout/core';
```

These are identical for both frameworks (React reads/writes exactly
the same shapes), so rather than a second, separately-maintained copy
of the same reference here, see the Vue package's own pages for the
full field-by-field breakdown of each:

- [Layout interface (ILayoutItem)](/vue/api/interfaces/layout/)
- [ARIA labels (IGridAriaLabels)](/vue/api/interfaces/aria-labels/)
- [Pluggable compaction (ICompactor)](/vue/api/interfaces/compactor/)
- [SVG export options](/vue/api/interfaces/svg-export-and-payload/)
- [Layout types (TLayout, TResponsiveLayout, TBreakpoint, TBreakpoints)](/vue/api/types/layout/)
- [ECompactType](/vue/api/enums/compact-type/)

See [GridLayout props](/react/components/grid-layout/props/) and
[GridItem props](/react/components/grid-item/props/) for where each of
these actually gets used.
