---
title: Layout persistence
description: useLayoutStorage, useAsyncLayoutStorage and useLayoutPresets — hooks for saving and loading a layout.
---

Unlike the Vue package, this package doesn't re-export
`serializeLayout`/`deserializeLayout` as standalone functions — import
those from `keystone-dashboard-layout-core` directly if you need the
raw building blocks for a backend other than `Storage` (a remote API,
IndexedDB, anything else). Both hooks below already use them internally.

Also unlike the Vue package's own versions (which operate on a
`Ref<TLayout>` you pass in and mutate directly), both hooks here follow
this package's own "you own the state, plain values in and out" shape —
`load()`/`loadPreset()` return the loaded layout for you to apply via
your own `setState`, and `save()`/`savePreset()` take the layout to
persist as an explicit argument, rather than reading/writing a ref.

## `useLayoutStorage`

```ts
function useLayoutStorage(
  key: string,
  options?: IUseLayoutStorageOptions,
): IUseLayoutStorageReturn;
```

```ts
interface IUseLayoutStorageOptions {
  storage?: Storage;   // default: window.localStorage
  autoSave?: boolean;  // default: false
  layout?: TLayout;     // the current layout to auto-save — required for autoSave to do anything
  debounceMs?: number;  // default: 500 — only relevant when autoSave is true
}

interface IUseLayoutStorageReturn {
  load: () => TLayout | null;
  save: (layout: TLayout) => void;
  clear: () => void;
  hasSaved: () => boolean; // whether *anything* is stored — not whether it's valid
}
```

SSR-safe — every storage access is guarded behind a `typeof window`
check; `autoSave` is a silent no-op during a server render rather than
throwing.

```tsx
function Dashboard() {
  const { load, save } = useLayoutStorage('my-dashboard-layout');
  const [layout, setLayout] = useState<TLayout>(() => load() ?? defaultLayout);

  function handleLayoutChange(next: TLayout): void {
    setLayout(next);
    save(next);
  }

  return <GridLayout layout={layout} onLayoutChange={handleLayoutChange}>{/* ... */}</GridLayout>;
}
```

Or with `autoSave` instead of an explicit `save()` call on every change:

```tsx
function Dashboard() {
  const [layout, setLayout] = useState<TLayout>(defaultLayout);
  const { load } = useLayoutStorage('my-dashboard-layout', { autoSave: true, layout });
  // ...
}
```

## `useAsyncLayoutStorage`

The asynchronous sibling of `useLayoutStorage`, for a layout that lives
behind a promise: a REST API, IndexedDB, a cloud document.

```ts
function useAsyncLayoutStorage(
  key: string,
  storage: IAsyncLayoutStorage,
  options?: IUseAsyncLayoutStorageOptions,
): IUseAsyncLayoutStorageReturn;
```

```ts
interface IAsyncLayoutStorage {
  getItem(key: string): Promise<string | null>;
  setItem(key: string, value: string): Promise<void>;
  removeItem(key: string): Promise<void>;
}

interface IUseAsyncLayoutStorageOptions {
  autoSave?: boolean;   // default: false
  layout?: TLayout;     // the current layout to auto-save — required for autoSave to do anything
  debounceMs?: number;  // default: 500 — only relevant when autoSave is true
  onError?: (error: unknown) => void;
}

interface IUseAsyncLayoutStorageReturn {
  load: () => Promise<TLayout | null>;
  save: (layout: TLayout) => Promise<boolean>;
  clear: () => Promise<boolean>;
  hasSaved: () => Promise<boolean>; // whether *anything* is stored — not whether it's valid
  isLoading: boolean;
  isSaving: boolean;
  error: unknown;                   // the latest store failure, or null
}
```

`createHttpStorage({ baseUrl })` (`GET`/`PUT`/`DELETE` on `baseUrl/key`,
optional `headers`, which may be a function for a refreshing token),
`createIndexedDbStorage()` and `createMemoryAsyncStorage()` come from
`keystone-dashboard-layout-core`. Or implement the three-method
`IAsyncLayoutStorage` yourself.

Nothing it returns rejects: a failing store sets `error`, calls `onError`, and
resolves `false` / `null`, so a fire-and-forget `save()` from `onLayoutChange`
never becomes an unhandled rejection. Writes run in call order through one
queue, so a slow earlier save cannot overwrite a later one, and `load()` waits
for saves already started. Create the store once (module scope or `useMemo`): a
new store object on every render starts a new queue.

```tsx
const storage = createHttpStorage({ baseUrl: '/api/layouts' });

function Dashboard() {
  const [layout, setLayout] = useState<TLayout>(defaultLayout);
  const { load, save, isLoading } = useAsyncLayoutStorage('my-dashboard-layout', storage);

  useEffect(() => {
    void load().then((stored) => stored && setLayout(stored));
  }, [load]);

  return (
    <GridLayout layout={layout} onLayoutChange={(next) => { setLayout(next); void save(next); }}>
      {/* ... */}
    </GridLayout>
  );
}
```

See the [Async persistence](/react/examples/async-persistence/) example.

## `useLayoutPresets`

```ts
function useLayoutPresets(
  key: string,
  options?: IUseLayoutPresetsOptions,
): IUseLayoutPresetsReturn;
```

```ts
interface IUseLayoutPresetsOptions {
  storage?: Storage; // default: window.localStorage
}

interface IUseLayoutPresetsReturn {
  savePreset: (name: string, layout: TLayout) => void;
  loadPreset: (name: string) => TLayout | null;
  deletePreset: (name: string) => void;
  listPresets: () => string[];
  hasPreset: (name: string) => boolean;
}
```

Layers on top of the same `serializeLayout`/`deserializeLayout`
building blocks, for saving and switching between **several named**
arrangements of the same items, rather than one single saved layout.
Every preset for a given `key` is stored together as one object under
one storage key — one read/write per operation, not one per preset.
SSR-safe, same guard as `useLayoutStorage`.

```tsx
function Dashboard() {
  const [layout, setLayout] = useState<TLayout>(defaultLayout);
  const { savePreset, loadPreset } = useLayoutPresets('my-dashboard');

  return (
    <>
      <button onClick={() => savePreset('compact', layout)}>Save as "compact"</button>
      <button onClick={() => {
        const loaded = loadPreset('compact');
        if (loaded) setLayout(loaded);
      }}>Load "compact"</button>
      <GridLayout layout={layout} onLayoutChange={setLayout}>{/* ... */}</GridLayout>
    </>
  );
}
```
