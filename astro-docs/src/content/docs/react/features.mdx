## Drag & resize

- **Drag anywhere, or from a handle.** Every item is draggable by default; restrict it to a specific handle with `dragAllowFrom`, or exclude specific elements with `dragIgnoreFrom` (and `resizeIgnoreFrom` for resize specifically). See [Drag allow/ignore elements](/react/examples/drag-allow-ignore-elements/) and [Custom drag handle](/react/examples/custom-drag-handle-close-button/).
- **Resize from any edge or corner** — top, right, bottom, left, and the diagonals — with optional `preserveAspectRatio` locking. See [Size constraints & aspect ratio](/react/examples/size-constraints-aspect-ratio/), [Restricting resize handles to specific edges](/react/examples/restrict-resize-handles/), and [Resize direction toggles](/react/examples/resize-direction-toggles/).
- **Min/max size constraints** (`minW`/`maxW`/`minH`/`maxH`) per item. See [Size constraints & aspect ratio](/react/examples/size-constraints-aspect-ratio/).
- **Bounded dragging** (`isBounded`) — keep items from being dragged outside the container. See [Bounded drag](/react/examples/bounded-drag/).
- **Static items** — lock specific items in place; they ignore dragging/resizing entirely and act as fixed obstacles for compaction. See [Static items](/react/examples/static-items/).
- **Per-item `zIndex` override** — pin one item permanently above every other, including while others are mid-resize, regardless of the library's own implicit static/resizing stacking rules. See [Per-item zIndex override](/react/examples/per-item-z-index/).
- **A separate header region** (the `header` render prop on `GridItem`) — an optional header area above an item's own main content, its own scrollable region taking whatever space remains. See [Custom header](/react/examples/custom-header-slot/).
- **Per-item `autoHeight`** — a live-resyncing height, driven by a real `ResizeObserver` on the item's own content rather than a one-time measurement. See [Per-item autoHeight](/react/examples/per-item-auto-height/).
- **`dragActivationDistance`** — a per-pointer-type drag-start threshold, so a small accidental movement doesn't immediately start a drag. See [Drag activation distance](/react/examples/drag-activation-distance/).

## Layout & collision

- **Automatic compaction.** Items fill gaps vertically by default; other items automatically move out of the way of a drag/resize.
- **Pluggable compaction strategy** (`compactType`) — five built-in strategies (vertical, horizontal, none, and overlap variants of each), or replace the algorithm entirely with a custom `compactor` prop. See [Pluggable compaction](/react/examples/pluggable-compaction/).
- **Horizontal shift mode** — push colliding items left/right instead of down. See [Horizontal shift](/react/examples/horizontal-shift/).
- **Prevent collision mode** (`preventCollision`) — block a drag/resize instead of pushing other items, with an `onMoveBlockedByCollision(id)` callback so a consumer can give feedback the moment that happens. See [Prevent collision](/react/examples/prevent-collision/) and [Blocked-move feedback](/react/examples/blocked-move-feedback/).
- **Magnetic snap-to-grid** (`snapToGrid`/`snapThreshold`) — actually adjusts an item's landing position to align with a neighbor, not just a visual guide. See [Snap to grid](/react/examples/snap-to-grid/).
- **Alignment guides** (`showAlignmentGuides`) — Figma-style guide lines while dragging or resizing, wherever an item's edges line up with another's. See [Alignment guides while dragging](/react/examples/alignment-guides/).
- **`restoreOnDrag`** — keep other items from compacting past their pre-drag position while a drag is in progress. See [Layout bounds & rendering options](/react/examples/layout-bounds-rendering-options/).
- **Auto-sizing container** — the grid's height grows/shrinks to fit its content by default (`autoSize`, or the newer `heightMode` prop for finer control including `'scroll'`/`'fit'` modes). See [Auto-size grid on content](/react/examples/auto-size-grid/) and [Height modes](/react/examples/height-modes/).
- **Spacing indicators** (`showSpacingGuides`) — a labeled distance badge (e.g. "2 cols") in the gap between the active item and its nearest neighbor on each side, independently toggleable alongside alignment guides. See [Spacing indicators](/react/examples/spacing-indicators/).
- **Serializable layout.** The `layout` array is a plain, JSON-serializable structure you own — persist it anywhere. See [Save/load layout](/react/examples/save-load-layout/).
- **Named layout presets** (`useLayoutPresets`) — save and switch between multiple named arrangements, layered on the same serialize/restore primitives. See [Named layout presets](/react/examples/named-presets/).
- **Grid-to-SVG export** (`exportLayoutAsSvg()` on the imperative handle) — a dependency-free utility producing a standalone SVG snapshot of the current layout. See [Export layout as SVG](/react/examples/svg-export/).
- **Undo/redo** (`enableUndoRedo`, capped via `undoHistoryLimit`) — opt-in history at committed-change granularity (drag/resize end, add/remove), not per intermediate frame. See [Undo/redo](/react/examples/undo-redo/).
- **Add/remove items freely**, with automatic re-compaction — no manual position math required. See [Add or remove items](/react/examples/add-remove-items/).
- **`distributeEvenly`** — spreads an out-of-bounds item to the next available slot on a responsive breakpoint change, instead of clamping it to the right edge.
- **`compactNow()`/`rearrange()`/`duplicateItem(id)`** on the imperative handle — force an immediate compaction pass, reflow the whole layout, or clone an existing item. See [compactNow, rearrange & duplicateItem](/react/examples/compact-now-rearrange-duplicate-item/).
- **Live layout lifecycle events** (`onLayoutReady`, plus the granular drag/resize callbacks) for observing exactly when the grid settles or an interaction completes. See [Layout lifecycle events](/react/examples/layout-lifecycle-events/).
- **Programmatic grid dimensions** — read/observe the container's own resolved width/columns directly. See [Grid dimensions](/react/examples/grid-dimensions/).
- **Switching layouts, including forcing a full remount** when a `key` change is the simplest way to reset internal state. See [Switching layouts & forcing a remount](/react/examples/switching-layouts-remount/).

## Multi-select & group operations

- **Select multiple items** (`multiSelect`) — click to select, Shift/Ctrl/Cmd+click to add additively, click empty background to clear. See [Multi-select & group move/resize](/react/examples/multi-select-group-move-resize/).
- **Group move and resize** — drag or resize any selected item and the rest of the selection moves or resizes by the same delta, from mouse or keyboard alike. See [Multi-select & group move/resize](/react/examples/multi-select-group-move-resize/).
- **Align/distribute commands** (`alignSelected(edge)`/`distributeSelected(axis)` on the imperative handle) — align a selection to an edge, or evenly space what's between. See [Align & distribute selected items](/react/examples/align-distribute-selected/).

## Responsive

- **Breakpoint-based column counts**, with sensible defaults and fully customizable `breakpoints`/`cols`. See [Responsive breakpoints](/react/examples/responsive-breakpoints/).
- **Pre-defined layouts per breakpoint** (`responsiveLayouts`), for full control over how content reflows instead of relying on auto-generation. See [Responsive predefined layouts](/react/examples/responsive-predefined-layouts/).

## Internationalization

- **RTL mirroring** (`isMirrored`) for an entire layout or individual items (per-item opt-out via `ILayoutItem.isMirrored`) — positions (and dragging) flip horizontally with a single prop. See [Mirrored (RTL)](/react/examples/mirrored-rtl/).

## Accessibility

- **Keyboard move & resize.** Every non-static, editable item is keyboard-focusable — arrow keys move it, Shift+arrow keys resize it — without needing any extra configuration, including RTL-aware key direction and `multiSelect` group-move/resize engagement. See [Accessibility scope](/react/guide/project/accessibility/) for the full scope, including what's deliberately not (yet) covered.
- **Screen reader support** — interactive items are announced with an item-role description and a description of the available keyboard controls; visible focus indicator for keyboard users.
- **Localizable ARIA strings** (`ariaLabels`) — the close button's label, role description, and the keyboard move/resize instructions are overridable (`GridLayout` grid-wide default, `GridItem` per-item override), rather than hardcoded English literals. See [Localizable ARIA strings](/react/examples/aria-labels/).

## Cross-grid & external drag-and-drop

- **Drag items from outside the grid** (`allowOutsideDrop`) using the browser's native HTML5 drag-and-drop API, with a live drop-position placeholder while dragging over the grid. See [Drag, drop from outside](/react/examples/outside-drag-drop/) and [outsideDropAccept & readOutsideDropPayload](/react/examples/outside-drop-accept-payload/).
- **Drag items between two independent grids** (`allowCrossGridDrag`/`disableExternalDrop`/`layoutId`) via a real first-fit bin-pack, not a naive placement then compaction sorts out. See [Drag, drop from grid to grid](/react/examples/cross-grid-drag-drop/) and [Cross-grid drop restrictions](/react/examples/cross-grid-drop-restrictions/).
- **Multiple grids on one page** with zero shared state or configuration beyond an optional `layoutId`. See [Multiple grids](/react/examples/multiple-grids/) and [Drag, drop from outside into multiple grids](/react/examples/outside-drag-drop-multiple-grids/).

## Styling & customization

- **Unstyled-by-default content** — `GridItem`'s children hold whatever you put there; the library only handles position/size.
- **Built-in close button** (`showCloseButton` + an `onItemClose` callback you handle yourself), or bring your own via the exported [`GridItemCloseButton`](/react/components/custom-close-button/)/[`GridItemDragHandle`](/react/components/custom-drag-element/) components. Any part of an item is a drag handle by default, restrictable via `dragAllowFrom`/`dragIgnoreFrom`. See [Show close button](/react/examples/close-button/) and [Custom drag handle & close button](/react/examples/custom-drag-handle-close-button/).
- **Configurable border radius** per item (`borderRadiusPx`/`useBorderRadius`, grid-wide default + per-item override). See [Border radius](/react/examples/border-radius/).
- **Optional grid line guides** (`showGridLines`), useful while building a layout or as a permanent visual aid. See [Show grid lines](/react/examples/grid-lines/).
- **Configurable transition duration/easing** (`transitionDurationMs`/`transitionTimingFunction`), applied via CSS custom properties. See [Configurable transition duration & easing](/react/examples/transition-duration-easing/).
- **Custom drag-placeholder content** — replace the default plain placeholder box with your own rendered content while dragging. See [Custom drag-placeholder content](/react/examples/custom-drag-placeholder/).
- **`scrollToItem`/`focusItem`** on the imperative handle — programmatically scroll an item into view and/or move keyboard focus to it. See [scrollToItem & focusItem](/react/examples/scroll-to-item-focus-item/).
- **`autoScroll`** — scrolls a container automatically near its edge during drag/resize. See [autoScroll](/react/examples/auto-scroll/).
- **Layout events** — a dedicated example covering the full set of granular drag/lifecycle callbacks together. See [Events](/react/examples/events/).
- **Edit-mode toggle** (`enableEditMode`) — a single grid-wide (or per-item) switch disabling dragging, resizing, and the close button at once. See [Edit mode toggle](/react/examples/edit-mode-toggle/).

## Developer experience

- **Full TypeScript support.** Every prop, callback, and interface is typed and exported from the package's main entry point — see [API](/react/api/) once that page lands.
- **Zero runtime dependencies.** The drag/resize engine is built on native Pointer Events, not a third-party library — the same shared engine the Vue package uses.
- **The same framework-agnostic core** (`keystone-dashboard-layout-core`) Vue uses for its own grid-layout math (collision detection, movement, compaction, and more) — both packages share one implementation of the hard, easy-to-get-subtly-wrong parts.
- **Idiomatic React.** A fully controlled component (`layout`/`onLayoutChange`), hooks instead of composables, Context instead of `provide`/`inject`, render props instead of named slots, and a `ref`-based imperative handle instead of `defineExpose` — the same underlying behavior, expressed the way React actually works.
- **Well-tested.** A real unit, mutation, and end-to-end test suite backs the package — see the package's own `docs/IMPLEMENTATION_PLAN.md` for the phase-by-phase history.
- **An editable playground on every example.** "Open in StackBlitz" opens a real, running project seeded from that exact example's own source, in a new tab — not a read-only code snippet.
