## Drag & resize

- **Drag anywhere, or from a handle.** Every item is draggable by default; restrict it to a specific handle with `dragAllowFrom`, or exclude specific elements with `dragIgnoreFrom` (and `resizeIgnoreFrom` for resize specifically).
- **Resize from any edge or corner** — top, right, bottom, left, and the diagonals — with optional `preserveAspectRatio` locking.
- **Min/max size constraints** (`minW`/`maxW`/`minH`/`maxH`) per item.
- **Bounded dragging** (`isBounded`) — keep items from being dragged outside the container.
- **Static items** — lock specific items in place; they ignore dragging/resizing entirely and act as fixed obstacles for compaction.
- **Per-item `zIndex` override** — pin one item permanently above every other, including while others are mid-resize, regardless of the library's own implicit static/resizing stacking rules.
- **A separate header region** (the `header` render prop on `GridItem`) — an optional header area above an item's own main content, its own scrollable region taking whatever space remains.
- **Per-item `autoHeight`** — a live-resyncing height, driven by a real `ResizeObserver` on the item's own content rather than a one-time measurement.
- **`dragActivationDistance`** — a per-pointer-type drag-start threshold, so a small accidental movement doesn't immediately start a drag.

## Layout & collision

- **Automatic compaction.** Items fill gaps vertically by default; other items automatically move out of the way of a drag/resize.
- **Pluggable compaction strategy** (`compactType`) — five built-in strategies (vertical, horizontal, none, and overlap variants of each), or replace the algorithm entirely with a custom `compactor` prop.
- **Horizontal shift mode** — push colliding items left/right instead of down.
- **Prevent collision mode** (`preventCollision`) — block a drag/resize instead of pushing other items, with an `onMoveBlockedByCollision(id)` callback so a consumer can give feedback the moment that happens.
- **Magnetic snap-to-grid** (`snapToGrid`/`snapThreshold`) — actually adjusts an item's landing position to align with a neighbor, not just a visual guide.
- **Alignment guides** (`showAlignmentGuides`) — Figma-style guide lines while dragging or resizing, wherever an item's edges line up with another's.
- **`restoreOnDrag`** — keep other items from compacting past their pre-drag position while a drag is in progress.
- **Auto-sizing container** — the grid's height grows/shrinks to fit its content by default (`autoSize`, or the newer `heightMode` prop for finer control including `'scroll'`/`'fit'` modes).
- **Spacing indicators** (`showSpacingGuides`) — a labeled distance badge (e.g. "2 cols") in the gap between the active item and its nearest neighbor on each side, independently toggleable alongside alignment guides.
- **Serializable layout.** The `layout` array is a plain, JSON-serializable structure you own — persist it anywhere.
- **Named layout presets** (`useLayoutPresets`) — save and switch between multiple named arrangements, layered on the same serialize/restore primitives.
- **Grid-to-SVG export** (`exportLayoutAsSvg()` on the imperative handle) — a dependency-free utility producing a standalone SVG snapshot of the current layout.
- **Undo/redo** (`enableUndoRedo`, capped via `undoHistoryLimit`) — opt-in history at committed-change granularity (drag/resize end, add/remove), not per intermediate frame.
- **Add/remove items freely**, with automatic re-compaction — no manual position math required.
- **`distributeEvenly`** — spreads an out-of-bounds item to the next available slot on a responsive breakpoint change, instead of clamping it to the right edge.

## Multi-select & group operations

- **Select multiple items** (`multiSelect`) — click to select, Shift/Ctrl/Cmd+click to add additively, click empty background to clear.
- **Group move and resize** — drag or resize any selected item and the rest of the selection moves or resizes by the same delta, from mouse or keyboard alike.
- **Align/distribute commands** (`alignSelected(edge)`/`distributeSelected(axis)` on the imperative handle) — align a selection to an edge, or evenly space what's between.

## Responsive

- **Breakpoint-based column counts**, with sensible defaults and fully customizable `breakpoints`/`cols`.
- **Pre-defined layouts per breakpoint** (`responsiveLayouts`), for full control over how content reflows instead of relying on auto-generation.

## Internationalization

- **RTL mirroring** (`isMirrored`) for an entire layout or individual items (per-item opt-out via `ILayoutItem.isMirrored`) — positions (and dragging) flip horizontally with a single prop.

## Accessibility

- **Keyboard move & resize.** Every non-static, editable item is keyboard-focusable — arrow keys move it, Shift+arrow keys resize it — without needing any extra configuration, including RTL-aware key direction and `multiSelect` group-move/resize engagement.
- **Screen reader support** — interactive items are announced with an item-role description and a description of the available keyboard controls; visible focus indicator for keyboard users.
- **Localizable ARIA strings** (`ariaLabels`) — the close button's label, role description, and the keyboard move/resize instructions are overridable (`GridLayout` grid-wide default, `GridItem` per-item override), rather than hardcoded English literals.

## Cross-grid & external drag-and-drop

- **Drag items from outside the grid** (`allowOutsideDrop`) using the browser's native HTML5 drag-and-drop API, with a live drop-position placeholder while dragging over the grid.
- **Drag items between two independent grids** (`allowCrossGridDrag`/`disableExternalDrop`/`layoutId`) via a real first-fit bin-pack, not a naive placement then compaction sorts out.
- **Multiple grids on one page** with zero shared state or configuration beyond an optional `layoutId`.

## Styling & customization

- **Unstyled-by-default content** — `GridItem`'s children hold whatever you put there; the library only handles position/size.
- **Built-in close button** (`showCloseButton` + an `onItemClose` callback you handle yourself), and any part of an item is a drag handle by default, restrictable via `dragAllowFrom`/`dragIgnoreFrom` — there's no separate exported close-button or drag-handle component to import.
- **Configurable border radius** per item (`borderRadiusPx`/`useBorderRadius`, grid-wide default + per-item override).
- **Optional grid line guides** (`showGridLines`), useful while building a layout or as a permanent visual aid.
- **Configurable transition duration/easing** (`transitionDurationMs`/`transitionTimingFunction`), applied via CSS custom properties.

## Developer experience

- **Full TypeScript support.** Every prop, callback, and interface is typed and exported from the package's main entry point — see [API](/react/api/) once that page lands.
- **Zero runtime dependencies.** The drag/resize engine is built on native Pointer Events, not a third-party library — the same shared engine the Vue package uses.
- **The same framework-agnostic core** (`keystone-dashboard-layout-core`) Vue uses for its own grid-layout math (collision detection, movement, compaction, and more) — both packages share one implementation of the hard, easy-to-get-subtly-wrong parts.
- **Idiomatic React.** A fully controlled component (`layout`/`onLayoutChange`), hooks instead of composables, Context instead of `provide`/`inject`, render props instead of named slots, and a `ref`-based imperative handle instead of `defineExpose` — the same underlying behavior, expressed the way React actually works.
- **Well-tested.** A real unit, mutation, and end-to-end test suite backs the package — see the package's own `docs/IMPLEMENTATION_PLAN.md` for the phase-by-phase history.
