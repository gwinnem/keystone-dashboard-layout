:::caution[A real, layered CI investigation — three bugs fixed (not yet re-verified), one still open]
**Bug 1 (fixed, confirmed via a live push)**: every workflow was failing
immediately at "Setup pnpm" — "Multiple versions of pnpm specified"
(`version: '9'` hardcoded in each workflow file vs. root `package.json`'s
own `packageManager`). Fixed by removing the hardcoded version from all
three workflow files; pushed, and confirmed gone — no job fails
instantly anymore.

**Bug 2 (fixed, not yet re-verified)**: with bug 1 fixed, every job
immediately hit a *different* failure — `Error [ERR_UNKNOWN_BUILTIN_
MODULE]: No such built-in module: node:sqlite`. Root cause: the
`packageManager` field had been bumped to `pnpm@11.22.0`, and pnpm 11
requires Node.js 22+ (dropping 18/19/20/21 support entirely) — but this
repo's own `engines` field, and most CI jobs, target Node 18/20. Fixed
by pinning `packageManager` to `pnpm@10.32.0` instead (still
actively maintained, unlike EOL'd pnpm 9, and compatible with the full
Node 18/20/22 range) — **not yet pushed/re-verified.**

**A third issue surfaced already, before bug 2's own fix was even
pushed**: with bug 1's fix alone live, the Node 22 leg of the CI matrix
got far enough to actually run the real test suite for the first time
ever — **437/437 Vitest tests passed** across Vue/React/Core — but the
job still failed overall, because `packages/angular`'s own
`test:coverage` step exited with code 1. Not yet root-caused: possibly
Node-22-specific (plausible, unconfirmed), possibly a genuine,
version-independent regression. Needs bug 2's fix pushed and a fresh
run to tell which.

**Bug 4 (fixed, not yet pushed) — the biggest finding**: pushing bug
1's fix alone let the Node 18 and Node 20 CI legs actually run for the
first time — and both failed for real. Node 18: `packages/core`'s own
`vite build` (which depends on `rolldown`) throws `SyntaxError: The
requested module 'node:util' does not provide an export named
'styleText'` — an API Node 18 never had. Investigating further
surfaced something bigger: **Node.js 18 reached end-of-life in April
2025, and Node.js 20 reached end-of-life in April 2026** — this
project's own `engines` field was claiming support for two
already-unsupported Node majors. Fixed by narrowing `engines.node` to
`>=22.0.0` across the root and all four packages, and narrowing
`ci.yml`'s own test matrix (plus the hardcoded Node version in
`mutation-testing.yml`/`release.yml`) to Node 22 only. **Also fixed**:
`check:licenses` was separately failing on the root workspace package
itself (a known `license-checker-rseidelsohn` quirk marking any
`"private": true` package `"UNLICENSED"` regardless of its own `license`
field) — fixed with `--excludePrivatePackages`. None of this batch
pushed/re-verified yet.
:::

## Code quality

- **Unit/component/hook tests passing** — confirmed via a direct read of `.github/workflows/ci.yml`: this package's own test suite is real and substantial, not a `passWithNoTests` placeholder (the workflow's own top comment states this explicitly) — exact current pass/fail counts still need `pnpm test` run directly for a live number.
- **Test coverage** — `pnpm test:coverage` runs as a blocking CI step (`ci.yml`'s own "Unit + component tests (with coverage gate)" step) on every push/PR — so a coverage regression genuinely fails CI, not just a local check nobody enforces. The exact current percentage still needs a direct run to quote a live number.
- **Mutation testing (Stryker)** — a real, confirmed capability, not just configured-but-untested: **overall mutation score 82.93%**, verified via a real run (up from 79.42% at an earlier check). Per-file breakdown as of the last confirmed run:
  - `useCrossGridDrag.ts` — 91.49%
  - `useGridItemDrag.ts` — 87.37%
  - `useGridItemResize.ts` — 78.05% at the last confirmed run; a further test fix (correcting a `calcWH` boundary value that didn't actually distinguish a `+`/`-` arithmetic mutant) was applied afterward but never re-confirmed with a fresh run — check current state rather than assume this crossed 80%.
  - `useLayoutPresets.ts` — 71.67%, and a known, deliberately-not-chased gap: most of its remaining survived mutants are on `useCallback`/`useMemo` dependency arrays (which don't affect a function's behavior when called, only whether React recreates it between renders) or on a `savePreset`/`deletePreset` early-return guard that's very likely a genuine equivalent mutant (bypassing it still routes through `readAllPresets`'s own separate, downstream null-storage guard, so there's no observable behavioral difference to test against). Not pursued further once the package's own overall score cleared 80%.
  - `useLayoutStorage.ts` — 86.27%.
- **Lint** — confirmed present and real: `eslint.config.js` exists for this package, and `pnpm lint` runs in CI (`ci.yml`'s own "Lint — advisory, not yet blocking" step) — but genuinely advisory (`continue-on-error: true`), not a merge-blocking gate. Actual current pass/fail output still needs a direct `pnpm lint` run to confirm.
- **`npm audit`** — confirmed covered, not skipped: `ci.yml`'s own dedicated `audit` job runs `pnpm audit --prod --audit-level=high` (blocking) and a broader `pnpm audit --audit-level=high` (advisory) from the monorepo root on every push/PR, which covers this package's own dependency tree along with every other package's. A production-dependency license check (`pnpm run check:licenses`) also runs, blocking. Not independently re-run by hand in this specific pass, but continuously enforced by CI rather than a one-off, unverified claim.

## Testing depth

Confirmed via a direct read of `.github/workflows/ci.yml` and this package's own `e2e/` directory: a real Playwright e2e suite exists and is wired into CI's own dedicated `e2e` job (installed and run for this package specifically, alongside Vue's — Angular's own package is excluded from that job, since it has no `test:e2e` script). 12 spec files cover basic grid rendering, drag & resize, keyboard accessibility, dynamic items, responsive breakpoints, external/cross-grid drop, multi-select, RTL, touch input, per-item overrides, and advanced features (blocked-move feedback, `compactNow()`, `duplicateItem`, `snapToGrid`, save/load layout) — see [Testing philosophy](/react/guide/project/testing/) for the full breakdown. Not independently re-run in this pass to confirm all 12 currently pass, but the suite's own existence and CI wiring are now confirmed, not assumed.

## Accessibility

Confirmed via a direct read of `GridItem.tsx`'s own source, not just the package's introduction claiming parity: keyboard-focusable non-static items (`tabIndex={0}`), arrow-key move / Shift+arrow resize (each a synthetic `dragstart`+`dragend` or `resizestart`+`resizeend` pair, so compaction/collision/`multiSelect` group-move handling applies identically to keyboard and mouse input), `role="group"`, `aria-roledescription`, and `aria-describedby`-linked move/resize instructions, all overridable via `IGridAriaLabels`. See [Accessibility scope](/react/guide/project/accessibility/) for the full writeup, including what's deliberately out of scope.
