The package exports these from its main entry point — both are
**standalone components**, added directly to your own component's
`imports` array, no `NgModule` required:

| Component | Selector | Purpose |
|---|---|---|
| [`GridLayoutComponent`](/angular/components/grid-layout/props/) | `kdl-grid-layout` | The grid container — owns the layout array, breakpoints, and collision/compaction logic. A fully controlled component (`layout` `@Input()` + `layoutChange` `@Output()`). |
| [`GridItemComponent`](/angular/components/grid-item/props/) | `kdl-grid-item` | A single draggable/resizable cell, projected as content of `GridLayoutComponent`. |

See [Styling](/angular/components/styling/) once that page lands for
the CSS custom properties and class names used throughout.

```ts
import { GridLayoutComponent, GridItemComponent } from '@keystone-dashboard-layout/angular';
```

There's no default export — always import by name. See
[Installation](/angular/guide/installation/) if you haven't added the
package yet.

This package also has real, exported close-button and drag-handle
components, matching Vue and React — but note that `GridItemComponent`'s
own built-in close button (`showCloseButton` + a `removeItem`
`@Output()` you handle yourself) is a separate, simpler path most
consumers should reach for first; the standalone components below are
for a consumer who wants the same building blocks rendered somewhere
else entirely (e.g. inside a custom header). Any part of a
`GridItemComponent` is already a drag handle by default — restrict it
via `dragAllowFrom`/`dragIgnoreFrom` directly on `GridItemComponent`,
without needing the standalone drag-handle component below at all,
unless you want its specific rendered widget.

## Standalone utility components

Two additional standalone components exist for a consumer who wants
the same close-button/drag-handle *building blocks* Vue's own
`CustomCloseButton.vue`/`CustomDragElement.vue` provide, used outside
`GridItemComponent`'s own built-in rendering entirely — e.g. placed
inside a custom header region (see `GridItemHeaderDirective` above).
Neither is used internally by `GridLayoutComponent`/`GridItemComponent`
themselves; a consumer opts into either explicitly.

| Component | Selector | Purpose |
|---|---|---|
| `GridItemCloseButtonComponent` | `kdl-custom-close-button` | A standalone close button. Takes a required `i` — the id of whichever item it should remove — and emits `removeGridItem` with that id on click; wire that output to your own removal logic. |
| `GridItemDragHandleComponent` | `kdl-custom-drag-element` | A standalone drag-handle widget (a labeled button plus a separate `.kdl-draggable-handle` hit-area — target that class, not the button itself, with `dragAllowFrom`). Takes an optional `text` input (default `'x'`) for the button's own label. |

```ts
import { GridItemCloseButtonComponent, GridItemDragHandleComponent } from '@keystone-dashboard-layout/angular';
```

## A real, notable difference from React

Unlike the React package (where `GridItem` only takes `i`, reading
everything else — position, size, `isDraggable`, and so on — off the
matching entry in `GridLayout`'s own `layout` array), `GridItemComponent`
here takes `i`/`x`/`y`/`w`/`h` as its **own, direct, required
`@Input()`s** — the same shape Vue's `GridItem` uses. You bind each one
explicitly per item in your own template's `@for` loop; this component
doesn't read them off `layout` automatically.

## The imperative API

`GridLayoutComponent` also exposes public methods, reached via a
template reference variable (`#grid` + `@ViewChild` in your own
component, or a plain template variable for a direct template call) —
`compactNow()`/`rearrange()`, `duplicateItem(id)`, `undo()`/`redo()`
(plus the `canUndo`/`canRedo` public fields), `selectItem()`/
`deselectItem()`/`toggleItemSelection()`/`clearSelection()`,
`alignSelected(edge)`/`distributeSelected(axis)`, `exportLayoutAsSvg()`,
and `scrollToItem(id)`/`focusItem(id)` — the Angular equivalent of
Vue's own `defineExpose`'d template-ref methods, or React's `ref`-based
imperative handle. See [Public members](/angular/api/) once that page
lands for the full reference.
