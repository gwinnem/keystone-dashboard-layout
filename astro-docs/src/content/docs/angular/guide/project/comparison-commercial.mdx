## Scope, and why this is separate from Comparison: alternatives

[Comparison: alternatives](/angular/guide/project/comparison-alternatives/)
scopes itself to open-source peers. This page covers five commercial
products instead. Kendo's actual component is called **TileLayout**
(available for jQuery, **Angular**, React, and Blazor) — this package
has a real, direct competitor here. **Syncfusion** ships a dedicated
**Angular Dashboard Layout** component, the closest of the five to a
general-purpose drop-in competitor. **DevExpress Dashboard** is a full
BI platform, not a standalone layout component — this page compares
against just its layout-authoring piece, since that's the only part in
the same category as this library. **Sencha Ext JS Dashboard**
(`Ext.dashboard.Dashboard`, accessible from Angular via the commercial
`@sencha/ext-angular` wrapper) is a real, long-standing dashboard
component built on an architecture unlike any of the other four — see
below. **Vaadin Dashboard** is a genuinely modern, actively-engineered
component with a real accessibility story — confirmed as a paid
Pro-tier component, not part of Vaadin's free Apache-2.0 core, and
worth a licensing/Angular-fit note of its own too.

Every claim below was independently verified against each vendor's own
current documentation, README, and API reference — not taken from a
single secondary report. The most load-bearing claims are quoted
directly. **"Not established"** still means the reviewed documentation
didn't confirm baseline-equivalent behavior, not proof the feature is
absent.

A note on **Vaadin Dashboard**'s fit here specifically: Vaadin's own
first-class framework integrations are Java (Flow) and React (Hilla) —
there is no dedicated Angular package. The underlying `vaadin-dashboard`
is a standard web component, so it's technically usable from Angular
via `CUSTOM_ELEMENTS_SCHEMA`, the same pattern Ignite UI Tile Manager
uses (see [Comparison: alternatives](/angular/guide/project/comparison-alternatives/))
— but Vaadin's own docs, examples, and typed bindings don't cover
Angular specifically, unlike the other four entries on this page.

## Architecture: four different models, not one

Kendo TileLayout and DevExpress Dashboard both build on structures
where resizing means dragging a **separator line** between adjacent
items, not independent per-item handles — Kendo's own docs describe
its layout as CSS Grid-based with `colSpan`/`rowSpan`, while DevExpress
Dashboard uses a recursive binary split-pane tree of layout groups.
**Ext JS Dashboard** is a third variant on the same theme: a
**column-stack layout**, confirmed directly in its own API docs —
`Ext.layout.container.Dashboard` "extends `Ext.layout.container.Column`
and adds splitters between adjacent columns allowing the user to
resize them." Items ("Parts") stack vertically within a column and
resize **only vertically**, dragged from the bottom edge — column
*width* is what the splitters adjust, not individual item width. This
library uses **freeform, independent `x`/`y`/`w`/`h` grid
coordinates** instead — the same general shape Syncfusion's own
Dashboard Layout and Vaadin Dashboard both use, though the two aren't
identical to each other or to this library: Syncfusion uses
grid-structured panels with upward-floating auto-arrangement,
functionally similar to this library's own vertical compaction, while
Vaadin's own docs describe widgets "placed in columns and rows
automatically, in the order supplied" with the **column count itself
adjusting responsively** to the dashboard's width — closer to a
responsive masonry/auto-flow model than fixed freeform coordinates.
None of these four approaches is strictly better — a constrained model
(Kendo, DevExpress, Ext JS) structurally guarantees no overlaps at the
cost of items never being fully independent of their neighbors;
freeform or auto-flow coordinates (this library, Syncfusion, Vaadin)
give more independent placement, at the cost of needing an explicit
collision/compaction system.

## Honest summary

Against **Kendo TileLayout**: a genuine, direct competitor for Angular
consumers specifically — this library is ahead on nearly every drag/
resize/layout-mechanics dimension: full 8-edge independent resize vs.
a single resize handler plus CSS Grid auto-flow, freeform positioning
vs. reorder-within-auto-flow, cross-grid drag, outside drop, snap/
alignment guides, undo/redo, and multi-select group operations.
Kendo's genuine advantages: being one component in a large commercial
suite with paid support, and per-item lock-against-rearrangement
documented directly (matching this library's own `isStatic`). One
nuance worth being direct about: Kendo's own documentation is
internally inconsistent on whether TileLayout has keyboard support at
all — its dedicated docs and API say yes, its shared package-overview
page says no.

Against **Syncfusion Dashboard Layout**: architecturally one of the
closer matches of the five, since it uses a freeform-ish grid model
with automatic compaction rather than separator-drag resizing — and
the one commercial product here with a real, unambiguously documented
accessibility gap this library specifically closes: Syncfusion's own
accessibility documentation states, verbatim, that keyboard support
does not apply to Dashboard Layout at all, where this library treats
keyboard move/resize as a first-class, always-available interaction
path (see [Accessibility scope](/angular/guide/project/accessibility/)).
Beyond that, this library is ahead on cross-grid drag, outside drop,
snap/alignment guides, undo/redo, multi-select, and SVG export — none
of which Syncfusion's own reviewed documentation establishes.
Syncfusion's genuine advantages: commercial support, built-in themes,
and a responsive single-column auto-stacking behavior with a
configurable media-query breakpoint that's more turnkey than authoring
per-breakpoint layouts by hand.

Against **DevExpress Dashboard**: not a real competitor for most
consumers — it's a BI-authoring product where drag/resize layout is
one supporting piece of a much larger data-analytics platform, not a
drop-in general-purpose layout primitive. The one genuine, real,
API-confirmed gap even at the pure layout-mechanics level is
**maximize/restore** (`MaximizeDashboardItem`/`RestoreDashboardItem`)
— tracked on the [Roadmap](/angular/guide/project/roadmap/), not yet
designed. Its own "Multiselection" feature is worth being precise
about too: it's a BI cross-filtering interaction (select data points
across items to filter a dashboard), a genuinely different concept
from this library's own layout-editing multi-select group move/resize
— not a feature this library is behind on, just a different one
wearing a similar name.

Against **Sencha Ext JS Dashboard**: a real, long-standing component
(the API class dates back years, still documented in current Ext JS
releases), but built on a meaningfully more constrained architecture —
column-stack with inter-column splitters, vertical-only per-item
resize, and drag-to-a-different-column/row rather than free
positioning. This library is ahead on essentially every layout-
mechanics dimension: full 8-edge resize vs. vertical-only, freeform
positioning vs. column-slot placement, cross-grid drag, snap/alignment
guides, undo/redo, and multi-select. Ext JS Dashboard's own genuine
strength, confirmed directly: **per-item lock against drag/resize**
with a real, documented example (specific "parts" configured as
neither draggable nor resizable while others stay interactive) — the
same shape as this library's own `isStatic`, independently confirmed
rather than assumed. Angular access is real but requires the
commercial `@sencha/ext-angular` layer on top of an Ext JS Enterprise
license — a meaningfully bigger commitment than installing an npm
package.

Against **Vaadin Dashboard**: the most interesting comparison on this
page, and the one commercial product here with a genuinely comparable
keyboard-accessibility story — Vaadin's own engineering writeup
confirms dedicated keyboard-based equivalents for moving and resizing
widgets, not just pointer gestures, with a stated WCAG 2.1 AA target.
This library is still ahead on cross-grid drag, outside drop, snap/
alignment guides, named presets, undo/redo, SVG export, and multi-select
— none of which Vaadin's own reviewed documentation establishes — but
Vaadin's responsive auto-flow column model (confirmed: column count
adjusts automatically to the dashboard's width) is a genuinely
different, well-engineered take on responsiveness worth knowing about
even where it isn't a feature gap either way. The real practical
caveat: Vaadin has no dedicated Angular integration at all — a
consumer would be reaching for a raw web component with none of the
Angular-specific documentation, typing, or examples the other four
entries on this page provide.

## What's not worth chasing from any of the five

- **Kendo's CSS Grid-based, single-handle resize model** — adopting
  this would be a regression, not a gap to close.
- **DevExpress's recursive split-pane structure itself**, or **Ext JS
  Dashboard's column-stack-with-splitters model** — rebuilding around
  either architecture would abandon the freeform positioning model
  that's core to what this library is.
- **DevExpress's BI/data-analytics layer entirely** — a different
  product category by design.
- **DevExpress's "Multiselection" concept as named** — a data-filtering
  feature, not a layout one; this library's own multi-select already
  covers the layout-editing use case that name might suggest.
- **Syncfusion's "keyboard support not applicable" stance** — this
  library treats keyboard accessibility as a baseline requirement, not
  an optional extra to skip.
