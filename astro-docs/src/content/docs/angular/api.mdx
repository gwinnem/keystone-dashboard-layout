Confirmed directly against `packages/angular/src/index.ts`, the
package's real public entry point — not assumed from the components
alone. As of this writing, that barrel exports seven things:

## What this package exports

```ts
import {
  GridLayoutComponent,
  GridItemComponent,
  GridItemHeaderDirective,
  GridLayoutStorageService,
  GridLayoutPresetsService,
  GridItemDragHandleComponent,
  GridItemCloseButtonComponent,
} from 'keystone-dashboard-layout-angular';
```

That's the complete list. Unlike the Vue package, this package doesn't
re-export layout-data types, enums, or compaction/ARIA interfaces
through its own barrel either — those come from the shared
`keystone-dashboard-layout-core` package directly instead (see
below). There's also no separate exported type for the
`@Input()`/`@Output()` shapes the way React exports `IGridLayoutProps`/
`IGridItemProps` — an Angular `@Component`'s own class already **is**
its prop contract; there's no separate props-interface convention to
mirror here.

:::caution[A real gap, not a documented limitation]
`GridItemHeaderDirective`, `GridLayoutStorageService`,
`GridLayoutPresetsService`, `GridItemDragHandleComponent`, and
`GridItemCloseButtonComponent` were fully implemented in the package's
own source but weren't actually exported from this barrel until a
recent fix — meaning no consumer could previously import any of these
five from `keystone-dashboard-layout-angular` at all, despite the
package's own `docs/IMPLEMENTATION_PLAN.md` already describing them as
finished, public API. Confirm you're on a version that includes the
fix before relying on these five specifically.
:::

## Components & directive

`GridLayoutComponent`, `GridItemComponent` — see
[Components](/angular/components/) for full `@Input()`/`@Output()`
documentation. `GridItemHeaderDirective`
is a marker directive with no inputs/outputs of its own — see
[GridItemComponent props](/angular/components/grid-item/props/#header-content)
for how it's used. The two standalone utility components,
[`GridItemCloseButtonComponent`](/angular/components/custom-close-button/)
and [`GridItemDragHandleComponent`](/angular/components/custom-drag-element/),
now each have their own dedicated reference page too.

## From `keystone-dashboard-layout-core`

The layout-data shape and framework-agnostic grid math live in `core`
rather than being re-exported from this package's own barrel. Import
these directly from `keystone-dashboard-layout-core` when you need
them:

```ts
import type {
  TLayout,
  ILayoutItem,
  IGridAriaLabels,
  ICompactor,
  IExportLayoutAsSvgOptions,
} from 'keystone-dashboard-layout-core';
import { ECompactType } from 'keystone-dashboard-layout-core';
```

`core` is the same package the Vue and React ports use underneath, so
the shapes themselves are identical either way — see this package's own
reference pages above for the full field-by-field breakdown of each,
framed for this package specifically.

See [GridLayoutComponent props](/angular/components/grid-layout/props/)
and [GridItemComponent props](/angular/components/grid-item/props/)
for where each of these actually gets used.
